Before the story

What is this page checking?

GPT-2 reads text step by step. Inside the model, sparse autoencoders carve its state into thousands of tiny "features," each of which lights up on a specific kind of text. Every feature gets an auto-generated label, like "cats," to describe it. We check whether that label matches the highlighted text and the full sentence the feature actually fires on.

The purpose of this page is to help you develop one basic habit: never take an LLM feature label at face value. The label may seem right despite the fact that the sentence itself has something else to say. In order to show you the dicrepancy, every example goes through an identical process: label, highlighted text, sentence, and verdict.

Therefore

Reading the dot map

How to read the 6,000-feature dot map.

Soon you will see a dot map of every feature in the dataset. Each dot is one feature. Features whose labels describe similar text end up near each other. The x and y axes don't carry meaning on their own — they're a flat squish of much higher-dimensional similarity, so what matters is which dots cluster together, not where they sit on the page.

Distance between dots reads as "their labels describe similar text," nothing more. Two dots far apart on the page may still share a topic — they just sit in different 2D positions because the squish has limits.

Takeaway

An auto-generated label is a starting point, not an answer.

The URL label passes, Python and Star Wars need context, and the cat label fails. The page keeps the label, highlighted text, and full sentence side by side so you can see why.

Conclusion: It is not to be understood here that labeling is pointless. Labels may be helpful, but they should be based on evidence. The correct interpretation should be consistent with the label, the activation text, and the whole sentence. A label is a confident description of what a feature does. But the firing pattern may not support that description, and the full sentence may tell a different story. The takeaway is simple: trust the label only when all three checks line up.

Why this matters

The same shape as hallucination.

The cat/cataracts disagreement is a tiny example of a confident description that doesn't match what's really happening. Hallucination — when an LLM confidently writes something false — has the same shape, one level up. If we can't trust the labels we use to read the model's insides, we're left with a harder version of the same question on the outside: was the output really backed by what the model actually did?

Inside the model

Feature-label mismatch

The auto-generated label says "cats." The feature actually fires on "cat" inside "cataracts." The label is a confident description that the firing pattern does not support.

Outside the model

Output hallucination

The LLM confidently writes a fact that isn't true. The output is a confident description that the world — or the model's own reasoning trail — does not support.

The fix is the same in both cases: don't trust a description on its own. Check it against the underlying evidence — the firing pattern for a feature, the source documents for a claim. That's what this page has been training your eye to do.
