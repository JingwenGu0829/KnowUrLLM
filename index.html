Prototype note

What is already working, and what is hardest next?

What we have done so far

The current prototype loads a public Neuronpedia dataset with 6,000 GPT-2 sparse-autoencoder features across all 12 residual-stream layers. It maps those features into a searchable D3 atlas and connects the atlas to layer filters, concept filters, density filtering, zoom, hover, and click details. It also includes aggregate views: a layer-by-category heatmap, an activation-density histogram, and legibility bars by layer. The detail panel uses cached Neuronpedia API examples to show token-level activation windows, so a student can compare the label, predicted tokens, and source text instead of trusting a dot alone.

What is hardest to design

The hardest design problem is explaining interpretability without overstating certainty. A feature can have a clean label but still activate on surprising token fragments, so the interface has to make uncertainty visible rather than hiding it behind a polished map. The atlas also contains heavy overplotting because thousands of features occupy the same projected space, which makes search, filtering, zooming, annotations, and selected examples essential. The next hardest piece is the final demo video: it needs to teach the interaction quickly while ending on the main takeaway that interpretability gives useful handles, not complete explanations.

Takeaway

Interpretability gives handles, not final answers.

A clear label can hide a messy feature. The cat example, for instance, can light up on "cataracts" because token fragments and words are not the same thing.

Categories here are a map layer, not ground truth. They help students explore, but the raw feature page is still the evidence to inspect.

The honest result: GPT-2 has many searchable internal handles, yet a feature label alone does not prove that the model understands a concept.
